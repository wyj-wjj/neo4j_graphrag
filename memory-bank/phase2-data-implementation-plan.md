## 1. 使用规则

- 严格按里程碑顺序推进；只有依赖已经通过测试时才允许并行实施互不依赖的步骤。
- 每一步只完成本步骤描述的范围，不顺带修改 Agent、检索阈值、生产数据库或阶段二真实 Adapter。
- 开始任何代码前，重新阅读 `architecture.md`、`phase1_env_checklist.md` 和 `phase2-data-spec.md`。
- 每一步完成后立即执行对应验证；只有达到通过标准后才在 `progress.md` 记录完成。
- 每个里程碑完成后运行该里程碑全部测试，并更新 `architecture.md`，只记录已经实现的真实行为。
- 先实现并验证 `ci-small`，再扩展 `dev-standard`；`staging-large` 只能通过显式命令物化。
- 大规模生成产物必须位于 Git 忽略目录或专用合成对象存储，禁止提交到仓库。
- 所有数据必须明确标记 Synthetic/Fake，生产配置必须拒绝加载生成器、故障控制面和合成执行器。
- CI 不调用收费模型。可选语言模型增强只能作为显式受控任务，且不能决定业务事实和评测真值。
- 独立 Oracle 不得直接调用被测应用的业务函数计算预期结果，防止同一错误同时污染实现和测试。
- 不读取或传播 `.env` 内容，不生成可用密码、Token、手机号、证件号、银行卡或真实地址。
- 修复数据生成 Bug 时先添加可复现的固定 Seed 测试，再修改生成逻辑；不得通过删除不变量放宽测试。

## 2. 里程碑零：范围、工作树与安全基线

### 步骤 0.1：核对权威文档

- 指令：按 AGENTS.md 顺序完整阅读全部权威文档，整理当前阶段一真实能力、阶段二数据范围和禁止事项。
- 验证测试：逐项回答 MySQL、Milvus、Neo4j、Redis、业务模拟器、长期记忆和真实写操作的真理源与边界。
- 通过标准：没有把计划能力描述成已实现能力；没有把动态订单事实计划写入 RAG 或长期记忆。

### 步骤 0.2：检查工作树和既有数据

- 指令：检查当前工作树、忽略规则、数据目录和测试资源，识别用户改动、来源不明数据和受保护资源。
- 验证测试：列出所有可能被生成器写入或清理的路径和资源前缀，并尝试对来源不明资源执行 dry-run。
- 通过标准：来源不明资源全部被排除；没有使用破坏性 Git 或数据库清理命令。

### 步骤 0.3：建立敏感信息基线

- 指令：对仓库和计划 Fixture 执行密钥与 PII 模式扫描，只记录风险类型，不传播已存在的值。
- 验证测试：放入明确无效的 Canary 样本，确认扫描器能发现测试目标且不会把它当真实凭据提交。
- 通过标准：仓库没有新增可用凭据、真实 PII 或真实业务数据；`.env` 保持忽略。

### 步骤 0.4：冻结数据工厂边界

- 指令：确定数据工厂为开发/测试工具，生产应用启动路径不得导入它；定义未来目录、依赖组和产物目录职责。
- 验证测试：绘制依赖方向并检查生产模块不依赖合成数据模块，Oracle 不依赖被测业务实现。
- 通过标准：数据工厂、业务模拟器、测试 Fixture 和生产运行时代码边界清楚且无循环依赖。

### 步骤 0.5：冻结初始版本与 Profile

- 指令：固定 `phase2-data-spec-v1`、`synthetic-commerce-v1`、`ci-small`、`dev-standard`、
  `failure-lab` 和 `staging-large` 的名称与初始规模。
- 验证测试：对重复名称、未知 Profile、非法版本和无 Seed 配置执行加载测试。
- 通过标准：合法配置唯一可解析；非法或含糊配置在生成任何文件前失败。

### 里程碑零验证

- 指令：汇总范围、安全、资源和版本核对结果，并在 `progress.md` 记录阻塞项。
- 验证测试：让另一名开发者或 AI 仅依据记录判断哪些数据可生成、哪些能力仍禁止。
- 通过标准：无需猜测真实/合成边界；没有未解释的文档冲突。

## 3. 里程碑一：工程骨架与公共数据契约

### 步骤 1.1：建立非生产数据工厂目录

- 指令：创建独立数据工厂、Schema、Profile、模板、Fixture、测试和生成产物目录，并为每个目录写职责说明。
- 验证测试：执行包发现和生产构建检查，确认数据工厂测试可导入而生产镜像不需要其开发依赖。
- 通过标准：目录职责明确；大规模产物目录已忽略；生产应用启动不加载数据工厂。

### 步骤 1.2：定义公共合成元数据 Schema

- 指令：定义 dataset、scenario、tenant、source、synthetic 标记、Schema 版本和生成规则版本等公共字段。
- 验证测试：构造合法、缺字段、额外字段、真实来源伪装和版本错误记录。
- 通过标准：合法记录严格往返；未标记 Synthetic/Fake 的生成记录被拒绝。

### 步骤 1.3：定义 Profile 配置 Schema

- 指令：为数量、比例、Seed、时间范围、格式分布、故障分布、输出格式和资源上限定义严格配置。
- 验证测试：测试比例不为 100%、负数数量、超出安全上限、未知字段和禁用 Profile。
- 通过标准：危险或不一致配置在生成前失败；默认不会物化 `staging-large`。

### 步骤 1.4：定义 Dataset Manifest Schema

- 指令：定义规范、生成器、Schema、规则、Seed、Profile、文件、数量、校验和、兼容版本和验证状态字段。
- 验证测试：测试完整 Manifest、缺少文件校验和、重复路径、数量不符和未知主版本。
- 通过标准：Manifest 能完整描述数据集；不完整或不可重放的数据集不能标记成功。

### 步骤 1.5：定义验证问题分类

- 指令：定义 Schema、关系、金额、时间、租户、权限、重放、泄漏、资源和确定性错误类别及稳定错误码。
- 验证测试：为每类错误建立最小失败记录并检查报告分类和定位字段。
- 通过标准：每个失败能定位 dataset、scenario、实体和不变量，不只输出无法追踪的异常文本。

### 步骤 1.6：建立小型固定 Fixture

- 指令：手工建立只含一个租户、少量用户、商品和订单的最小有效 Fixture，用于验证公共加载器。
- 验证测试：加载两次并比较对象、顺序和序列化结果；逐个破坏关键字段验证失败。
- 通过标准：有效 Fixture 稳定；所有关键字段缺失或跨租户引用均被拒绝。

### 步骤 1.7：建立数据工厂测试分组

- 指令：区分快速单元、契约、不变量、集成、规模、故障和人工审核测试，并设置清晰标记。
- 验证测试：分别收集每个测试组，检查默认 CI 不会误运行百万级生成或收费模型任务。
- 通过标准：测试组可独立执行；快速门禁无外部网络和大资源依赖。

### 里程碑一验证

- 指令：运行 Schema、Profile、Manifest、错误分类和最小 Fixture 全部测试。
- 验证测试：从空临时目录创建并验证一份最小 Manifest，不连接任何业务数据库。
- 通过标准：公共契约稳定，生产路径无数据工厂依赖，架构文档已记录实际新增目录。

## 4. 里程碑二：确定性、时间、金额与原子导出

### 步骤 2.1：实现稳定 Seed 派生规则

- 指令：从根 Seed 按领域和版本派生独立 Seed，保证新增一个领域不会改变其他领域既有样本。
- 验证测试：用相同根 Seed 运行两次，再新增物流子配置并比较既有身份和订单结果。
- 通过标准：相同输入完全一致；新增领域不会重排或改变无关记录。

### 步骤 2.2：实现确定性合成 ID

- 指令：按固定命名空间、固定基准时间、领域和序号生成稳定且符合项目约定的测试 ID。
- 验证测试：跨进程、跨运行顺序和跨 Profile 生成相同逻辑实体并比较 ID，同时检查领域间碰撞。
- 通过标准：同一实体 ID 稳定，全数据集无碰撞，不依赖 Python Hash 随机化。

### 步骤 2.3：实现固定 UTC 时间轴

- 指令：从 Profile 固定基准时间生成所有业务时间，并提供合法的单调事件偏移。
- 验证测试：更换执行机器时区并重复生成；构造逆序、无时区和超范围时间。
- 通过标准：输出时间完全一致且带 UTC 时区；非法时间线被拒绝。

### 步骤 2.4：实现 Decimal 金额生成

- 指令：统一金额精度、舍入、币种和上下限，禁止在中间计算中使用浮点数。
- 验证测试：覆盖折扣、税费、运费、部分退款、边界分值和累计舍入。
- 通过标准：金额公式逐分一致；序列化往返不丢精度。

### 步骤 2.5：实现稳定排序和流式批次

- 指令：为每类记录指定稳定排序键，并按可配置批次流式生成和导出。
- 验证测试：改变批次大小、线程调度和输入集合顺序，比较最终记录顺序和校验和。
- 通过标准：批次与调度不改变内容；生成过程不需要一次性加载全部记录。

### 步骤 2.6：实现原子输出目录

- 指令：先写临时数据集目录，完成全部验证后再原子发布；失败产物不得冒充成功数据集。
- 验证测试：在写入中段、校验前和发布前注入中断，检查最终目录和临时诊断。
- 通过标准：成功目录始终完整；失败运行没有成功 Manifest，且可安全清理。

### 步骤 2.7：实现文件校验和与数量核对

- 指令：记录每个文件的相对路径、记录数、大小和 SHA-256，并核对 Manifest 汇总数量。
- 验证测试：修改一个字节、删除一条记录、添加未登记文件和交换文件顺序。
- 通过标准：所有篡改和数量差异被发现；相同生成输入校验和一致。

### 里程碑二验证

- 指令：在两个独立临时目录生成相同最小数据集并逐文件比较。
- 验证测试：比较确定性文件 Hash，并执行中断恢复和非法金额/时间负例。
- 通过标准：确定性差异为零，失败发布不会留下可加载半成品。

## 5. 里程碑三：租户、身份、权限与商品事实

### 步骤 3.1：生成租户和租户等级

- 指令：生成 Standard、Enterprise、Regulated 合成租户及其时区、状态、隔离策略和配额配置。
- 验证测试：测试租户 ID 唯一、保留前缀、禁用租户和跨 Profile 稳定性。
- 通过标准：所有租户明确 Synthetic，禁用租户不能产生可用业务会话。

### 步骤 3.2：生成用户、部门和角色

- 指令：按租户生成 customer、customer_service、supervisor、knowledge_admin、auditor 和 tenant_admin。
- 验证测试：检查角色集合、部门归属、用户唯一性、缺少角色和跨租户角色引用。
- 通过标准：身份关系完整；跨租户角色或部门引用为零。

### 步骤 3.3：生成无效联系信息

- 指令：只生成 `.invalid` 邮箱、全零或遮罩联系字段和虚构地址，保证不可联系且能测试脱敏。
- 验证测试：运行 PII、邮箱、电话、地址和密钥扫描，并抽样检查所有格式。
- 通过标准：可联系信息和真实 PII 数量为零；脱敏测试仍能识别 Canary。

### 步骤 3.4：生成角色和 ABAC 矩阵

- 指令：为租户、角色、部门、地域、密级、有效期和显式 Deny 生成可计算的权限矩阵。
- 验证测试：覆盖允许、Deny 优先、缺少策略、过期、下线、跨租户和权限依赖不可用。
- 通过标准：Oracle 只允许明确有效访问；不确定或依赖失败一律拒绝。

### 步骤 3.5：生成商品、SKU 和售后类别

- 指令：生成虚构分类、商品、SKU、价格、税率、库存属性、售后类别和别名。
- 验证测试：测试 SKU 唯一、价格精度、分类关系、组合商品、虚拟商品、预售和不可退商品。
- 通过标准：商品关系完整且无真实品牌；不可退和特殊商品规则可被 Oracle 识别。

### 步骤 3.6：生成租户配额和成本基线

- 指令：为每类租户生成 QPS、Token、存储、文档和 Tool 调用配额，仅作为合成规则。
- 验证测试：测试配额内、边界、超限、重置、禁用和跨租户计数。
- 通过标准：计数与租户隔离；合成配额不会被文档表述为生产建议。

### 里程碑三验证

- 指令：运行身份、权限、PII、商品和配额不变量测试，并导出 `ci-small` 对应数据。
- 验证测试：随机抽取每个租户和角色执行允许/拒绝矩阵对照。
- 通过标准：权限误允许和跨租户污染为零，所有联系信息不可用。

## 6. 里程碑四：订单事实与独立 Oracle

### 步骤 4.1：定义并生成订单状态机

- 指令：生成 created、paid、allocated、shipped、delivered、closed、cancelled 和 refund_pending 等合法状态。
- 验证测试：枚举合法边、非法跳步、重复事件、回退状态和终态后继续更新。
- 通过标准：只有规范允许的状态迁移成功；非法迁移有稳定原因。

### 步骤 4.2：生成订单明细和金额

- 指令：生成商品明细、数量、单价、优惠、运费、税费和应付金额，并保留计算依据。
- 验证测试：独立重算每笔订单，覆盖零运费、满减、部分优惠、边界金额和多币种拒绝。
- 通过标准：全部订单逐分相等；不支持币种在生成阶段被拒绝。

### 步骤 4.3：生成订单归属和访问场景

- 指令：为本人、同租户他人、客服授权队列、跨租户、不存在和已归档订单生成访问标签。
- 验证测试：使用独立权限 Oracle 计算每种身份的可见性和脱敏字段。
- 通过标准：跨租户和未授权订单不可见；合法客服只看到授权范围。

### 步骤 4.4：生成地址快照与改址规则

- 指令：生成虚构地址快照、变更次数、出库状态、高价值标签和审批要求。
- 验证测试：覆盖未出库可改、已出库拒绝、次数超限、高价值审批和幂等重复。
- 通过标准：改址允许性由确定性规则决定；任何地址都不可用于真实投递。

### 步骤 4.5：生成多包裹和部分履约订单

- 指令：生成拆包、部分发货、部分签收、缺货和预售混合订单。
- 验证测试：核对每个明细与包裹数量、履约状态和可退款数量。
- 通过标准：订单汇总与所有包裹/明细一致，无负库存或超量履约。

### 步骤 4.6：生成订单异常和错误语义

- 指令：生成不存在、归属错误、状态冲突、版本冲突、重复请求和暂时不可用场景。
- 验证测试：检查每个场景的稳定错误码、可重试性和用户可见信息。
- 通过标准：鉴权/验证错误不可重试；瞬时错误与业务拒绝可区分。

### 步骤 4.7：实现独立订单 Oracle

- 指令：独立计算订单可见性、可改址性、金额、可退款明细和期望错误，不调用被测 Order Adapter。
- 验证测试：用手工小样本验证 Oracle，再对全部 `ci-small` 订单执行交叉不变量检查。
- 通过标准：手工答案完全一致；Oracle 与事实记录之间没有无法解释差异。

### 里程碑四验证

- 指令：导出并重新加载 `ci-small` 订单数据，运行状态、金额、权限和 Oracle 测试。
- 验证测试：随机选择正常、部分履约、不可改址和跨租户订单进行端到端事实复算。
- 通过标准：主外键、金额、时间、权限和状态机通过率均为 100%。

## 7. 里程碑五：物流事实与异常场景

- 指令：从已发货订单派生一个或多个包裹、明细分配、虚构承运商和追踪编号。

### 步骤 5.3：生成物流异常

- 验证测试：对每类异常检查预期客服行为、是否允许催单和是否转人工。
- 通过标准：异常标签完整；系统动作与订单/物流事实一致。

### 步骤 5.4：生成催单频控与幂等场景

## 8. 里程碑六：退款、审批、幂等与补偿事实

### 步骤 6.1：实现退款试算 Oracle

- 指令：根据订单明细、已退金额、售后类别、运费和政策版本计算最大可退金额及拒绝原因。
- 验证测试：覆盖全额、部分、不可退、超额、重复、舍入和订单状态变化。
- 通过标准：退款结果逐分可重算，累计退款不超过可退金额。

### 步骤 6.2：生成退款草单

- 指令：生成草单 ID、订单快照 Hash、原因码、证据 ID、请求金额、风险级别、有效期和幂等键。
- 验证测试：检查缺少快照、过期、重复相同请求和同键冲突载荷。
- 通过标准：合法草单完整；重复回放或冲突行为确定。

### 步骤 6.3：生成风险矩阵

- 指令：按金额、订单状态、租户等级、角色、风险标签和重复行为生成合成审批要求。
- 验证测试：覆盖阈值两侧、黑名单、角色不足、策略版本变化和风险服务不可用。
- 通过标准：高风险默认转审批或拒绝；模型无法修改矩阵结果。

### 步骤 6.4：生成审批任务和事件

- 指令：生成 created、pending、approved、rejected、expired 和 cancelled 状态，以及审批人角色快照。
- 验证测试：测试合法决定、重复相同决定、冲突决定、越权审批和过期后批准。
- 通过标准：审批状态机确定；越权、冲突和过期批准均不触发执行。

### 步骤 6.5：生成严格隔离的合成执行结果

- 指令：只在独立业务模拟器中生成 synthetic_execute、reconciled 和结果未知状态，强制 Fake 来源。
- 验证测试：用生产配置、非合成租户、未审批草单和错误策略版本尝试执行。
- 通过标准：所有危险尝试被拒绝；合成执行不会调用任何真实外部端点。

### 步骤 6.6：生成执行幂等和冲突场景

- 指令：为批准后的执行生成稳定幂等键、首次结果、重复回放和载荷冲突。
- 验证测试：重复 2～10 次并检查执行记录、资金模拟流水和审计数量。
- 通过标准：相同请求只产生一次合成副作用；冲突请求不覆盖既有结果。

### 步骤 6.7：生成结果未知与对账场景

- 指令：生成请求超时但可能已执行、回调丢失、查询确认、最终成功和最终失败场景。
- 验证测试：检查未知结果时禁止盲目重试，必须先按幂等键查询或对账。
- 通过标准：不存在因超时自动重复执行；最终状态可由对账解释。

### 步骤 6.8：生成 Saga 补偿场景

- 指令：生成后续步骤失败、可补偿、补偿失败和人工介入状态，并保存前后快照。
- 验证测试：验证补偿只能针对已完成步骤、重复补偿幂等、失败进入人工流程。
- 通过标准：状态可追溯；补偿不会超过原副作用或掩盖失败。

### 步骤 6.9：实现退款与审批终态 Oracle

- 指令：独立计算每个场景的允许下一动作、最终状态、允许副作用和禁止副作用。
- 验证测试：使用手工审批矩阵和全部 `ci-small` 退款场景交叉检查。
- 通过标准：未审批关键写操作为零；所有终态可由事实和策略版本解释。

### 里程碑六验证

- 指令：运行金额、草单、风险、审批、执行、对账、补偿和幂等测试。
- 验证测试：在每个安全边界注入中断并按 Oracle 恢复或转人工。
- 通过标准：重复副作用和未审批执行均为零，Fake 标记遗漏为零。

## 9. 里程碑七：知识源、版本、格式与证据锚点

### 步骤 7.1：定义虚构知识主题和政策规则

- 验证测试：检查每条政策有租户、权威等级、适用范围、有效期、来源和唯一规则 ID。

- 通过标准：文档与 Schema 一致，其他开发者无需读生成器实现即可理解数据。

### 步骤 14.6：更新当前架构和进度

- 指令：只把已完成的数据工厂、模拟器、Profile 和测试写入 `architecture.md`，在 `progress.md` 记录结果和限制。
- 验证测试：对比代码、Schema、Manifest、CI 和文档中的状态声明。
- 通过标准：没有把未实现 Profile、Kafka 或真实 API 描述成已完成。

### 步骤 14.7：完成 AI 交接检查

- 指令：让未参与实现的 AI 回答如何新增领域、场景、Profile、Anchor、Oracle、故障和评测 Case。
- 验证测试：要求其定位真理源、禁止边界、验证命令和安全清理流程。
- 通过标准：回答不需要猜测关键路径，不建议绕过正式入库或直接写派生索引。

### 步骤 14.8：生成阶段二数据工厂验收报告

- 指令：执行全部快速门禁、完整数据 Job、全链路集成、安全、重建和文档检查，冻结验收 Manifest。

### 里程碑十四验证

- 指令：在干净环境从固定版本重建最终 `ci-small` 和 `dev-standard`，并核对验收报告。
- 验证测试：比较校验和、Oracle、评测、资源清单和文档声明。
- 通过标准：数据工厂可重复、可验证、可清理、可交接，且没有真实副作用或虚假生产结论。

## 17. 最终完成定义

只有同时满足以下条件，阶段二合成数据工厂才算完成：

- `ci-small` 和 `dev-standard` 可由固定配置与 Seed 重复生成，业务文件校验和差异为零。
- Profile、Manifest、Schema、独立 Oracle、验证报告和资源所有权形成闭环。
- 身份、商品、订单、物流、退款、审批、知识、会话、事件、安全和故障数据全部具备。
- 所有金额、时间、状态机、关系、租户、权限、幂等和审批硬不变量通过率为 100%。
- 跨租户污染、真实 PII、真实凭据、未审批关键写操作和未标记 Fake 结果数量为零。
- 知识数据通过正式入库链路生成 Chunk、Milvus 和 Neo4j 派生索引。
- `synthetic-gate-v2`、`security-v2` 和 `memory-v2` 达到规范规模并通过对应门禁。
- 自动生成数据没有被错误命名为 Golden；Golden Candidate 具有独立审核入口。
- 大规模产物不进入 Git，清理默认 dry-run 且只作用于 Manifest 所有资源。
- 生产配置无法启用合成业务执行、故障控制面或 Fake 回调。
- 文档、CI、测试、Manifest 和当前真实架构保持一致，其他开发者或 AI 可以继续维护。
